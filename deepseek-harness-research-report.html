执行摘要

DeepSeek Harness（dsh）是 DeepSeek 官方的开源 Agent Harness，处于 developer preview 阶段（v0.1.2-alpha.1）。它构建在源码内 vendored 的 Cordis 框架之上，采用"一切皆插件"架构：模型适配器、工具注册表、会话日志乃至 agent loop 本身都是可由配置替换的插件，没有特权内核。

  • 规模：247 个 workspace 包（56 个分组）+ 9 个 vendored 框架包，2,640 个 TypeScript 源文件、约 56.0 万行 TS；另含 Python SDK（约 2,900 行）与原生 Landlock 沙箱模块（C）。
  • 速度：2026-06-10 至 2026-08-28 的 80 天内产生 14,226 次提交（日均约 178 次），46 位贡献者，1,203 个已合并 PR，PR 编号已达 #3248。
  • 工程纪律极高：逐文件 100% 测试覆盖率门禁、43 个 verify-* 静态门禁、约 606 篇 implemented 决策记录（Agent Notes）、机器强制的文档字数预算与中英双语配对、129 个录制会话快照场景。
  • 能力完备：shell/subprocess/终端/文件系统/沙箱/子代理/工作流/技能/网络/LSP 等 20+ 能力接缝；同时提供 Web GUI、Headless、SDK（TS/Python）、ACP 四种应用形态，并可与 Claude Code / Codex 互操作（hook 桥 + 子代理 provider）。
  • 主要风险：pre-release 无任何兼容承诺（首个 tagged release 前可自由重命名）、vendored Cordis 上游漂移检测尚未落地（供应链敞口）、深度绑定 DeepSeek 模型生态、项目仅 80 天历史且无外部生产采用案例。
总体判断：这是一个"流程成熟度远超版本号"的项目——以牺牲发布速度换取正确性基座（仓库自述 stance：foundation over blast radius）。其定位是"开源、可组合的 Agent 框架 + 参考实现"，工程纪律显著高于同类开源项目；适合作为企业构建自研 Agent 平台的架构参考或基座候选，但当前版本不具备生产稳定性承诺。

一、项目概况

1.1 项目定位

  • DeepSeek AI 官方 Agent Harness，MIT 协议，全仓 ESM（"type":"module"）。
  • 设计哲学："没有特权核心"——扩展方式是"在插件树旁边挂载一个插件"，而非修改内核；新行为一律走文档化扩展点（Plugins, not loop changes）。
  • 预发布立场：正确性基座优先于爆炸半径——首个 tagged release 前允许自由重命名/重打包，后端拒绝旧盘上格式（SESSION_FORMAT_VERSION=0，无兼容承诺）。
  • 5 个内置 profile：web（默认，127.0.0.1:3080）、headless、sdk、sdk-minimal、acp，全部经唯一启动器 dsh CLI 启动。

1.2 核心设计不变量（节选）

  • Model-visible ⟺ Logged：到达模型请求的一切必须可从会话日志重构，有运行时不变量断言。
  • Registrations are effects：一切注册经 ctx.effect()/ctx.on()，返回 disposer，卸载按序回卷。
  • Explicit > Implicit：默认值必须是显式 resolve(request): Spec 步骤（dsh-shell 为模板），禁止 run() 内隐藏 ?? default。
  • Fail-loud：误配置在加载期或最早可解析点响亮失败，绝不静默跳过。
  • 不透明跨边界 id 必须 branded（Branded<B>），禁裸 string。

1.3 三类事件域

3.2 Turn 执行流（一次回合）

turn ⊇ steps：turn 由 turn/start|end 包裹，可含多 step；每个 step = 一次模型调用 + 它请求的工具执行。

阶段机制
输入认领loop 认领 inbox 消息（通道：send / followup / steer / inject，分别对应本轮/下轮/唤醒/不唤醒）
pre-stepagent/pre-step waterfall：可 enter（改写消息）或 reject（turn 以 blocked 结束）；compaction 压力检查在此触发
组装请求SystemPrompt.assemble() → agent/request waterfall 提出 LlmCallConfig → 写 request/header、request/context
流式响应chunk 逐条追加 assistant/chunk；错误走 agent/request-error waterfall 决定 retry（llm-retry 插件）或抛错
工具执行并发调度：isConcurrencySafe 且 parallel 模式进有界滚动池（默认上限 10），否则独占形成 barrier；结果按模型顺序提交
收尾agent/turn-stopping serial 钩子；中断时已流出前缀落为 interrupted 消息、未派发调用补合成 tool/result

四、Cordis 插件模型（框架层）

4.1 能力接缝三角色（capability seam）

角色职责
Service Definition拥有 ctx.<key> 与词汇类型的抽象类（"never a TypeScript interface"），如 ShellExecutor
Service Provider具体实现，每组合恰好一个（重复注册即抛错），如 bash-local / pwsh-local
Consumer注入使用的模型可见工具，如 tool-bash

规范示例：dsh-shell（Definition）→ dsh-bash-local / dsh-bash-sandbox（Provider）→ dsh-tool-bash（Consumer）。接缝必须三角色完整，缺一不可。

4.2 五种事件派发模式

模式语义
emit不等待，纯通知
waterfall不等待、有返回值、around 中间件；监听者必须调用 next() 委托，否则短路链
parallel / serial等待全部/逐个监听者
bail首个 bail 值停止

事件 JSDoc 强制 @mode 标签；类型化事件用 declaration merging + merge-extensible maps。

5.1 系统提示词组装

  • section（有序命名、重名抛错、scoped 遮蔽 global）/ context（动态上下文）/ variable（严格插值，未知引用抛错）/ tools provider 四类注册，全部经 Cordis effect 管理。
  • 排序用稀疏整数位（HARNESS_IDENTITY=-1000 … STRUCTURED_OUTPUT=9900）；complete:true section 可整体替换 preset 提示词。
  • 渲染结果写入 request/header 事件（model-visible ⟺ logged）；动态 context 物化为持久 user 消息快照，参与重放与压缩。

5.2 工具执行管线

参数 schema 校验（execute 前自动类型化）
→ tools/pre-execute：allow / deny / ask 审批
→ 单调 ToolGuard（只可否决不可放行）
→ tools/execute around-dispatch（可换 deadline signal）
→ tools/post-execute：accept / replace / block / 附加上下文
→ finalizeContent → tools/result 观察

Host presenter 必须是纯函数（无 I/O、无时钟），同一函数同时服务实时流与日志重放；结果卡片元数据持久化于 tool/result 的 meta 字段。

5.3 上下文压缩（compaction）

  • 三条路径：压力触发（默认 thresholdRatio 0.8 开始压缩、retainRatio 0.16 保留尾部）、上下文溢出恢复（agent/request-error 后压缩并从新 surface 重试）、/compact 手动命令（busy 时拒绝、排队 prompt FIFO 执行）。
  • 替换实现为 surface 级 {op:'replace', start, end}，两端必须 tool-pairing 平衡；被遮蔽节点记入 sourceEventSeqs，replaceGeneration 递增——原始事件永不删除，重放可完整还原。
  • 配套 compaction-tool-result-pruner：先裁 oversized 工具输出，可能免去整段总结。

七、数据平面：会话、状态与设置

7.1 会话持久化

  • 唯一事实源 = append-only SessionEvent 日志；JSONL 后端默认（Zstandard 校验帧 + chunk 打包），SQLite 为 opt-in 单库（schema 18，单调 SCHEMA_VERSION，无迁移）。
  • 读取侧 fail-closed：构建不认识的任何事件类型（当前词汇表 48 个类型）拒绝重建日志并给出诊断（含 "newer harness" 方向提示），绝不静默跳过。
  • 崩溃恢复不截断：为未应答调用补合成 tool/result（TOOL_NOT_STARTED / TOOL_OUTCOME_UNKNOWN），只丢弃未写全的 torn tail。
  • 投影（projection）单元 = key + stateSchema + 同步 apply；session-projection-cache 持久化 checkpoint 使冷读免全量回放。

7.2 设置 / 凭证 / 身份

  • settings：命名空间 + 三层解析（schema 默认 < 组合 base < user 文档）；YAML 热编辑保注释、跨进程写锁、原子替换；秘密字段 describe 可剥离。
  • credentials：密钥从配置剥离为按名引用；解析顺序：启动环境快照 > 存储文件（唯一可写层）> 项目 .env > home .env。
  • identity：纯随机 UUID（crypto.randomUUID，绝不派生自机器信息），用于 OTel user.id 与 DeepSeek 请求头。
  • 遥测：部署装且仅装一个后端（shipped 为 OTel；FULL / FEEDBACK_ONLY / DISABLED 三模式）；每条记录过 redaction waterfall，throwing 监听者 fail-closed 扣留。

7.3 日志态产品包（todo / plan）

  • todo：todo_write 工具每次提交整表快照（last-write-wins），单 owner 归属调用 agent；下一 turn 开始清空 standing plan（turn/end 保留已完成项）。
  • plan mode：log-only 整值 plan/mode 事件；引导而非限制——所有工具保持可用；exit_plan_mode 审批走 user-questions 的 plan-review intent；无问答通道时 fail-closed，/plan off 是手动出口。

八、人机协作平面：命令、审批与防护

8.1 审批模型（fail-closed）

  • ctx.approval：一次性 allow/reject 审批；结果四值封闭 allowed-once / rejected / cancelled / unavailable——缺 answerer、非 owner、抛错一律 fail-closed 到 unavailable。
  • 策略 ask（默认）| never（服务内确定性拒绝，prepend 监听者也无法绕过——headless/CI 立场）。
  • 审计为 log-only 事件对 approval/asked + approval/decided（invariant 校验配对），不进模型上下文。
  • permission-presets：捆绑 sandbox 模式 + 审批策略两个旋钮（默认 workspace-write+ask）；自身不做 enforcement，挂载要求 confining bash executor + approval service 同时在场。

8.2 问答与命令（独立通道）

  • user-questions：通用问答 waterfall，schema 带 intent（如 plan-review）；被父代理拥有的子 agent 不可发起（DELEGATED_CALLER），须把未决问题写进最终结果。
  • tool-ask-user：把问答暴露为模型工具，答案以 JSON 文本回流，不改 loop 机制。
  • commands：slash 命令注册表，无模型往返直接执行；agent-scoped 可遮蔽全局同名；每次 run 记入会话日志。

8.3 防护插件（guard 家族）

插件行为
repeat-tool-reminderadvisory never veto：检测（工具名 + 规范化参数）完全相同的连续重复调用，第 3/5/8 次注入提醒（合成 user 消息，可从日志重建）；新 user prompt 清链
tool-call-timeout-policy协作式 deadline：只对自报 timeoutMs 的工具生效（内置 bash/read 等不触碰）；超时替换为 TOOL_TIMEOUT 错误结果；不硬杀——工具忽略 signal 则等到自然 settle

9.2 Typert RPC（自研类型化 RPC）

  • 构建期 generator 把 TS 源类型编译为编译器无关 TypeGraph，发射 Zod v4 schema + 反射工件（tsdown 插件集成）。

十一、安全模型

11.1 纵深防御栈

层机制
内核围栏（进程）sandbox-local 按平台探测链选后端：Linux：bwrap → landlock（bwrap 剖面更接近承诺所以优先）；macOS：Seatbelt（sandbox-exec）；Windows：ACL 受限令牌（CreateProcessAsUserW + kill-on-close Job）。无法强制时 fail-closed 报 SANDBOX_UNAVAILABLE，绝不裸跑
原生 Landlock 启动器native/landlock-run：约 300 行 C11（musl 静态链接），self-restrict-then-exec——先给自身装 ruleset（no_new_privs，跨 execve 继承）再 exec 目标，host 不受限；fail-closed 退出码 125；故意无安装期编译 fallback；CLI 契约钉死并有三道发布门
用户态围栏（fs 缝）fs-sandbox：workspace-write 模式下重新 canonicalize fresh target 再交底层写（消除 check-here-write-there TOCTOU）；dev/ino 身份回退兼容 8.3 名；自我定位是 containment 而非安全边界，内核级隔离归沙箱执行器
审批沙箱升级梯子（read-only→workspace-write→danger-full-access）：模型可用 sandbox_permissions + justification 一次性重试，先经 ctx.approval 用户批准（allowed-once 才授予本次）
环境卫生子进程环境按 /KEY|PASSWORD|SECRET|TOKEN/i 与 DSH_ 前缀清洗；spill 目录 0700 私有 mkdtemp；settings/凭证文件 0600

11.2 动态执行隔离

  • workflow 脚本：worker thread + vm realm，仅放行 plain JSON 跨 realm；meta 绝不在宿主 eval。
  • 动态插件：node:vm 沙箱、Node globals 缺失或重定向到 Cordis 服务 façade；README 明言"vm 隔离 globals 但不是安全边界——视同 bash 权限"；浏览器侧动态包必须人工批准。

11.3 维护者侧规则（与产品沙箱严格区分）

  • Host sandbox failures 规则：必需命令被 host 沙箱挡住时，用最窄的 host 提权原样重试，必须提供 sandbox 证据，绝不借机绕过测试失败或产品沙箱。
  • Windows 是一等平台：PR 必经"Wine 里跑真 win-x64 Node"阻塞门 + 真实 Windows runner 三条 lane（build/native tests/observational）。
